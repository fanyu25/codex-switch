# Codex Switch：同服务商跨身份续接对话设计需求

## 1. 文档定位

本文是 `codex-switch` 的设计目标与需求文档，用于约束后续脚本改造、测试和发布验收。它描述目标行为，不表示当前实现已经满足。

本设计以服务商 URL 作为对话续接的安全边界：仅允许在**同一个规范化 API 基础 URL**下共享与续接对话。不同 URL、URL 缺失或无法确定 URL 的档案，不参与跨身份会话续接。

本文不记录 API Key、登录令牌、服务端 URL 的实际值或 HTTP 头。

## 2. 核心目标

### 2.1 同服务商身份切换

当当前档案与目标档案指向同一个规范化服务商 URL 时，任意 API Key 和 ChatGPT/Codex 登录身份必须稳定续接全部旧对话。

“稳定续接”至少包括：

1. 对话在统一列表中可见、可搜索、可打开并完整阅读。
2. 切换 API Key、模型或 ChatGPT 登录后，对话不会消失、复制、覆盖或被隐藏。
3. 用户可选择任意旧会话继续发送消息；新消息与旧历史属于同一条可追溯对话链。
4. 续接不应因 API Key 或同服务商账户切换而出现 provider 元数据不匹配、会话不可见或加密状态错误。
5. 认证信息保持隔离；共享的是 `CODEX_HOME` 中的会话与本地上下文，绝不共享凭据。

```text
服务商 URL A + API Key 1 创建对话
             ↓
切换到服务商 URL A + API Key 2 或 ChatGPT 登录
             ↓
同一会话仍可见、可读、可稳定续接
```

### 2.2 跨服务商保护

当前档案与目标档案的 URL 不相同、任意一方 URL 缺失或 URL 无法规范化时，系统必须**拒绝切换**，并保持切换前的版本完全不变：

- 当前 `auth.json` 不变；
- 当前 `config.toml` 不变；
- 当前会话文件、SQLite 状态、附件和历史索引不变；
- 当前正在运行的客户端不刷新、不重启；
- 向用户报告“服务商 URL 不一致，已取消切换并保留当前档案”。

这不是“先切换再回滚”的弱保证。正确流程是在写入认证、配置或会话元数据**之前**完成 URL 校验，因此失败路径没有任何状态变更。

```text
当前 URL A ── 目标 URL A ──> 允许切换并共享/续接会话
当前 URL A ── 目标 URL B ──> 拒绝切换，保留当前版本
当前 URL A ── 目标未知  ──> 拒绝切换，保留当前版本
```

## 3. 服务商 URL 识别规则

### 3.1 URL 来源

系统必须从当前生效的 `~/.codex/config.toml` 与目标 `profiles/<名称>/config.toml` 中解析活动 `model_provider` 对应配置段的 `base_url`。

对于没有独立 `config.toml` 的 ChatGPT/Codex 登录档案，应使用显式配置的 `CODEX_DEFAULT_OPENAI_BASE_URL`；未设置时使用程序定义的官方 OpenAI 默认 URL。若实际客户端配置无法证明该默认值，必须视为“未知 URL”，而不是猜测为同一服务商。

### 3.2 规范化

比较前应将 URL 规范化，以避免等价写法导致误判：

1. 仅接受 `http://` 或 `https://` URL。
2. 协议和主机名转换为小写。
3. 移除查询参数、片段和结尾多余的 `/`。
4. 保留协议、端口和路径；`https://example.com/v1` 与 `https://example.com/v2` 必须视为不同。
5. 不跟随重定向，也不依据 IP、证书、页面内容或品牌名称推断“同一服务商”。

规范化后的字符串完全相等，才可认定为同一个服务商。例如，大小写差异或末尾斜杠差异可以相同；不同域名、端口、协议或 API 路径必须不同。

## 4. 切换流程

```text
请求切换目标档案
        ↓
获取互斥锁，读取当前与目标配置
        ↓
解析并规范化两侧活动服务商的 base_url
        ↓
URL 相同？────否────> 报错并退出；当前版本不变
        │
       是
        ↓
备份当前 auth.json 与 config.toml
        ↓
原子写入目标 config.toml 与 auth.json
        ↓
同步同服务商的共享会话元数据
        ↓
同步成功？──否──> 从备份恢复 auth.json、config.toml 与会话状态
        │
       是
        ↓
按需刷新 VS Code；可执行 codex resume --all
```

档案名称校验、文件锁、权限控制和成对备份必须继续保留。同步步骤不得跨 URL 重写会话文件或 SQLite 中的 provider 元数据。

## 5. 功能需求

| 编号  | 优先级 | 需求                                                  | 验收要点                                                     |
| ----- | ------ | ----------------------------------------------------- | ------------------------------------------------------------ |
| FR-01 | P0     | 系统解析当前和目标档案的活动服务商 URL。              | API 档案从活动 provider 段读取 `base_url`；ChatGPT 档案使用明确的默认 URL 规则。 |
| FR-02 | P0     | URL 规范化比较准确且可审计。                          | 覆盖大小写、尾部 `/`、端口、路径、查询参数、片段、缺失 URL 和无效 URL。 |
| FR-03 | P0     | 同一规范化 URL 的档案可切换并共享全部旧对话。         | API Key A、API Key B、ChatGPT 登录三种身份在同 URL 下均能打开并稳定续接全部历史。 |
| FR-04 | P0     | 不同、缺失或无法识别 URL 的档案必须拒绝切换。         | 命令以非零状态退出；认证、配置、会话、SQLite、附件的哈希与切换前一致。 |
| FR-05 | P0     | 切换后同步失败时必须完整回滚。                        | 模拟同步失败；恢复前后 `auth.json`、`config.toml`、会话和索引一致。 |
| FR-06 | P1     | `status` 显示当前规范化 URL 与档案兼容状态。          | 仅显示脱敏的 URL 身份信息或哈希，不输出凭据。                |
| FR-07 | P1     | `list` 或独立检查命令显示各档案与当前档案是否可切换。 | 相同 URL 显示“可共享”；不同/未知显示“已阻止”。               |

## 6. 命令行为

### 6.1 `use <profile>`

`use` 必须在 `backup_active`、复制 profile 文件、同步会话或刷新 VS Code 前执行 URL 兼容性检查。

- URL 相同：允许原有切换流程，随后可用 `--resume [SESSION_ID]` 续接共享会话。
- URL 不同或未知：不创建备份、不复制文件、不刷新 VS Code，直接失败并说明比较结果。

### 6.2 `login <profile>` 与 `api <profile>`

这两个命令会创建或更新认证资料，URL 兼容性必须在最终写入档案前再次验证：

- 新 API 的输入 URL 与当前 URL 不一致时，取消操作并恢复/保留原状态。
- ChatGPT 登录若指向默认 OpenAI URL，只能与相同默认 URL 的当前档案共享会话。
- 新建不同 URL 的档案不应自动接管当前共享会话；需要先在隔离的配置空间中完成创建，或提供明确的“仅保存、不激活”操作。

### 6.3 `resume`

`resume` 只允许在已经通过同 URL 检查的当前档案上执行。它使用 `codex resume --all` 打开统一会话列表；不实现跨 URL 的强制续接、provider 重标记或加密内容迁移。

## 7. 加密内容与会话完整性

同服务商 URL 是安全前提，但不同账户或 API Key 下是否可解密历史仍必须由真实续接测试验证。不得通过删除 `encrypted_content`、伪造 provider、静默重写历史或只显示会话列表来制造“共享成功”的表象。

对于同 URL 仍无法续接的会话，系统必须：

1. 立刻停止本次切换或续接操作；
2. 恢复切换前认证、配置和会话状态；
3. 报告会话 ID、失败阶段和安全的恢复方式；
4. 将该问题视为 FR-03 未满足，不能降级为只读或新建无历史对话。

## 8. 非功能需求

- **原子性**：所有可能影响切换的写入必须使用临时文件、原子替换、备份与可验证的回滚。
- **并发安全**：使用 `flock` 或等效锁，避免两个切换同时写入认证、配置或会话状态。
- **最小变更**：URL 检查不写入 profile、备份、会话、SQLite 或客户端状态。
- **安全性**：日志不得泄露 API Key、OAuth Token、HTTP 头或完整 URL；必要时使用哈希/脱敏标识。
- **可观测性**：记录比较结论（相同/不同/未知）、规范化结果摘要、是否发生写入和是否回滚；不记录秘密值。

## 9. 验收场景

| 场景                 | 操作                                                         | 预期结果                                       |
| -------------------- | ------------------------------------------------------------ | ---------------------------------------------- |
| 同 URL API → API     | 使用同一规范化 URL 的 Key A 创建对话，切换至 Key B 并续接。  | 全部旧对话可见、可读、稳定续接。               |
| 同 URL API → ChatGPT | API 和 ChatGPT 档案均识别为同一默认/显式 URL，切换后续接。   | 全部旧对话可见、可读、稳定续接。               |
| 不同 URL API → API   | 当前 URL A，目标 URL B。                                     | 切换命令失败；所有受保护文件哈希保持不变。     |
| URL 缺失             | 目标 profile 无活动 provider URL，且不是可证明的默认 ChatGPT 档案。 | 切换命令失败；所有状态保持不变。               |
| URL 写法等价         | 仅域名大小写或结尾 `/` 不同。                                | 规范化后判定为相同，允许切换。                 |
| 路径不同             | 同域名但 `/v1` 与 `/v2`。                                    | 判定为不同，拒绝切换并保持当前版本。           |
| 同 URL 同步失败      | 允许切换后故意让同步工具返回失败。                           | 自动回滚认证、配置及会话状态，并返回非零状态。 |
| 加密续接失败         | 同 URL 下选择带加密内容的旧会话续接并触发失败。              | 恢复状态并报告失败；不改写历史、不降级为只读。 |

## 10. 当前基线与差距

当前 `bin/codex-switch` 已实现 URL 解析、规范化比较和切换前门禁：`use`、`api` 与 `login` 在写入认证、配置或 profile 前拒绝不同、缺失或无效 URL。切换前会将当前账号最后使用的 `config.toml` 回写到唯一匹配的 profile；无匹配 profile 时允许创建新账号，多个匹配 profile 时拒绝切换以避免覆盖错误配置。同 URL 切换后仍使用统一的 `CODEX_HOME` 与 `codex-provider sync`。同步命令失败时，脚本会恢复先前的 `auth.json` 与 `config.toml`；会话与 SQLite 的事务回滚由 `codex-provider-sync` 负责。

该实现已经覆盖 FR-01 至 FR-05 的脚本控制流，但尚未完成真实 API Key、ChatGPT 登录、加密历史和 provider-sync 会话回滚的端到端验收。完成第 11 节全部发布门禁前，不能向用户承诺稳定续接已被实际验证。

## 11. 发布门禁

只有同时满足下列条件，才能将本设计标记为完成：

1. FR-01 至 FR-05 的自动化测试通过。
2. 同 URL 的 API Key A、API Key B、ChatGPT 登录完成双向切换与全部旧会话续接测试。
3. 不同、缺失和无效 URL 的切换测试均证明没有任何受保护状态发生改变。
4. 同 URL 同步失败和加密续接失败均完成完整回滚测试。
5. 日志、状态输出、备份和错误报告通过凭据泄露审查。

## 12. 相关路径

```text
bin/codex-switch         # 仓库内的 Bash 脚本
tests/                   # 不访问真实认证信息的回归测试
docs/                    # 设计与实施计划

$CODEX_SWITCH_HOME       # 运行时 profile、备份与切换锁；默认 ~/.codex-switch
$CODEX_HOME              # 运行时配置、认证、会话、附件与 SQLite 状态；默认 ~/.codex
```

## 13. 运行与归档

仓库内可直接执行帮助、列表和回归测试：

```bash
./bin/codex-switch help
bash tests/test_codex_switch_config_persistence.sh
```

完整的 `use`、`api`、`login` 和 `resume` 功能不是无依赖运行：本机必须已安装 `codex` CLI；涉及历史同步的操作还需要 `codex-provider`，可通过 `CODEX_PROVIDER_SYNC_BIN` 指定其可执行文件。安装为本机命令时可执行：

```bash
install -m 700 bin/codex-switch "$HOME/.local/bin/codex-switch"
```

本文基于仓库内 `bin/codex-switch`、`tests/` 及会话同步工具检查编写；文档不记录任何认证信息。
